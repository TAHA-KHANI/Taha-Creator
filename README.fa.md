# راهنمای طاها کریتور برای Railway

نسخهٔ بازسازی: `6.0-railway` — راه‌اندازی تازه، با حفظ موتور قدیمی دکمه‌سازی و بازسازی لایهٔ اجرا و مدیریت اصلی.

این بسته هنوز روی حساب واقعی Railway و با توکن‌های واقعی تو دیپلوی نشده است. وضعیت دقیق آزمون‌ها در `docs/VALIDATION.fa.md` نوشته شده. «وجود قابلیت در سورس» با «آزموده‌شدن تمام حالت‌های آن در تلگرام» فرق دارد؛ این بسته ادعای بی‌نقص‌بودن همهٔ مسیرهای سورس قدیمی را ندارد.

## ۱. دقیقاً چند ربات داریم؟

| بخش | در نسخهٔ اصلی | کارش چیست؟ | چه کسی استفاده می‌کند؟ |
|---|---|---|---|
| ربات اصلی، یا ربات‌ساز | `Pedar.php` | ثبت توکن ربات تازه، سکه، دعوت، فهرست ربات‌ها، فروشگاه و مدیریت مالکیت | تو و کاربرانی که اجازه بدهی |
| ربات مدیریت مرکزی | `bot.php` | مدیریت کاربران و سکهٔ ربات‌ساز، آمار کل، نسخه‌ها و ربات‌ها | فقط `OWNER_ID` |
| ربات فرزند | نسخه‌ای از `Haji.php` | رباتی که کاربر می‌سازد؛ پنل دکمه‌سازی و تنظیمات خودش را دارد | مالک همان ربات، ادمین‌هایش و کاربرانش |

پس برای شروع **دو توکن جدا** لازم داری. برای تست ساخت ربات، یک **توکن سوم** هم از BotFather می‌گیری. لازم نیست برای هر ربات در Railway سرویس جدید بسازی. یک سرویس برنامه + یک MySQL، همراه فضای دائمی برنامه، میزبان همهٔ آن‌ها می‌شوند.

توکن هر ربات مثل رمز آن است. شناسهٔ عددی تو با یوزرنیم `@...` فرق دارد. API ID، API Hash، شماره تلفن و سشن اکانت تلگرام لازم نیست؛ این پروژه Bot API است.

## ۲. قبل از شروع

- حساب GitHub و دسترسی به Railway لازم است.
- توکن‌های داخل ZIP قدیمی را استفاده نکن. اگر متعلق به تو هستند، در BotFather آن‌ها را تعویض کن؛ در سورس به‌صورت آشکار وجود داشتند.
- این بسته دیتابیس کاربران قبلی را ندارد. کد به‌تنهایی کاربران، موجودی‌ها و تنظیمات هاست قدیمی را منتقل نمی‌کند. برای نصب تازه از MySQL خالی استفاده کن.
- هزینه و ظرفیت Railway به پلن حساب خودت بستگی دارد. این پروژه اجرای رایگان دائمی را تضمین نمی‌کند. برای هر دو سرویس و Volume بودجه تعیین کن.

## ۳. ساخت ربات‌ها در تلگرام

۱. ربات رسمی و تأییدشدهٔ `@BotFather` را باز کن.
۲. `/newbot` را بفرست؛ نام نمایشی دلخواه و سپس یوزرنیم آزاد بده که به `bot` ختم شود.
۳. اولین توکن را برای **ربات‌ساز** نگه دار: `CREATOR_TOKEN`.
۴. دوباره `/newbot`؛ ربات دوم برای **مدیریت مرکزی**: `MANAGER_TOKEN`.
۵. ربات سوم را برای تست بساز و توکنش را فعلاً نگه دار؛ آن را در Variables دو ربات اصلی وارد نکن.
۶. هر دو ربات اصلی را باز کن و Start بزن. قبل از اجرا جواب ندادنشان طبیعی است.

### شناسهٔ عددی خودم را از کجا بگیرم؟

به ربات مدیریت یک پیام بفرست. قبل از راه‌اندازی، در مرورگر آدرس زیر را با توکن همان ربات باز کن:

```text
https://api.telegram.org/botYOUR_MANAGER_TOKEN/getUpdates
```

در پاسخ، بخش `message` سپس `from` سپس `id` شناسهٔ توست. آن عدد را برای `OWNER_ID` بردار؛ عدد موجود در `chat.id` فقط در گفت‌وگوی خصوصی خودت همین است. این آدرس توکن دارد؛ آن را به کسی نده و از اسکرین‌شاتش توکن را پاک کن. بعد از نصب، `/id` در ربات مدیریت هم شناسه را نشان می‌دهد.

اگر `result` خالی است، یک پیام تازه به ربات بده و صفحه را تازه کن. اگر خطای فعال‌بودن webhook دیدی، از یک ربات مدیریتی تازه استفاده کن تا ربات دیگری را ناخواسته قطع نکنی.

## ۴. رساندن سورس به GitHub

در مخزن باید خودِ `Dockerfile`، `railway.json` و پوشه‌های `app`، `bin`، `public` و `tests` دیده شوند. **آپلود تنها فایل ZIP کافی نیست.** پوشهٔ اضافه دور پروژه هم نگذار؛ Dockerfile باید در ریشه باشد.

### اگر کامپیوتر داری

ZIP را استخراج کن. در GitHub یک مخزن خصوصی تازه بساز، Add file → Upload files را بزن و فایل‌ها و پوشه‌های استخراج‌شده را با ساختارشان منتقل و Commit کن. مطمئن شو پوشهٔ `.github` هم منتقل شده تا آزمون خودکار اجرا شود.

### اگر فقط گوشی داری

می‌توانی از Codespaces در مرورگر با حالت Desktop site استفاده کنی. پردازش آن روی سرور انجام می‌شود.

۱. در GitHub یک مخزن خصوصی مثل `taha-creator-railway` بساز؛ گزینهٔ ساخت README را روشن کن تا مخزن یک commit داشته باشد.
۲. Code → Codespaces → Create codespace on main را بزن. در صورت تفاوت رابط، صفحهٔ `https://github.com/codespaces/new` را باز و مخزن خودت را انتخاب کن.
۳. وقتی محیط ویرایشگر باز شد، در Explorer روی فضای خالی کلیک راست/لمس طولانی کن و Upload را بزن؛ فایل ZIP بازسازی‌شده را بارگذاری کن.
۴. Terminal → New Terminal را باز کن. اگر نام فایل دانلودشده فرق دارد، آن را دقیقاً به `TAHA-CREATOR-Railway.zip` تغییر بده. سپس این دستورها را **داخل مخزن تازهٔ خودت** اجرا کن:

```bash
unzip -o TAHA-CREATOR-Railway.zip
rm TAHA-CREATOR-Railway.zip
git add app bin public tests docs tools .github Dockerfile railway.json README.fa.md .env.example .gitignore .dockerignore
git commit -m "Add Railway rebuild"
git push
```

۵. به صفحهٔ مخزن برگرد؛ اکنون باید `Dockerfile` را کنار فایل‌ها ببینی. در تب Actions نتیجهٔ Validate را ببین. اگر قرمز است، جزئیات همان خطا را بررسی کن و فعلاً سرویس را عمومی نکن.
۶. بعد از کار Codespace را Stop کن تا بی‌دلیل روشن نماند. سهمیه و هزینهٔ Codespaces را در حساب خودت بررسی کن.

توکن‌ها را داخل GitHub، README یا فایل PHP نگذار. `.env.example` صرفاً نمونه است و به‌صورت خودکار توسط Railway خوانده نمی‌شود.

## ۵. ساخت پروژهٔ Railway

۱. در Railway یک پروژهٔ تازه بساز.
۲. از New / Create، یک دیتابیس **MySQL** اضافه کن؛ نه PostgreSQL. نام سرویس را `MySQL` بگذار تا نمونهٔ متغیرهای پایین بدون تغییر کار کند.
۳. صبر کن MySQL آماده شود. Volume دیتابیس را حذف نکن.
۴. داخل همین پروژه، سرویس دیگری از GitHub Repo ایجاد و مخزن سورس را انتخاب کن.
۵. Railway باید `Dockerfile` را تشخیص بدهد. Build Command و Start Command سفارشی لازم نیست؛ این دو را خالی بگذار.
۶. برای **سرویس برنامه** یک Volume بساز و Mount path را دقیقاً `/data` بگذار. این Volume جدا از Volume خود MySQL است. فایل‌های ربات‌های فرزند و وضعیت‌های فایل‌محور آنجا می‌مانند.
۷. تعداد Replica را **۱** نگه دار. این نسخه صف تک‌پردازشگر دارد و برای چند Replica طراحی نشده است.
۸. اگر گزینهٔ Serverless / Sleep روشن است، آن را برای این سرویس خاموش کن تا پردازش صف متوقف نشود.

در نخستین تلاش، قبل از تنظیم متغیرها خطای Missing variable طبیعی است؛ بعد از تکمیل تنظیمات Redeploy می‌کنی.

## ۶. متغیرهای ضروری

روی **سرویس برنامه** برو، نه سرویس MySQL. تب Variables را باز کن و این موارد را وارد کن. در مقدار توکن و شناسه، علامت نقل‌قول نگذار.

| نام | مقدار |
|---|---|
| `CREATOR_TOKEN` | توکن ربات اول |
| `MANAGER_TOKEN` | توکن ربات دوم |
| `OWNER_ID` | شناسهٔ عددی خودت |
| `APP_SECRET` | یک رشتهٔ تصادفی حداقل ۳۲ کاراکتری؛ پیشنهاد ۶۴ کاراکتر |
| `MYSQLHOST` | `${{MySQL.MYSQLHOST}}` |
| `MYSQLPORT` | `${{MySQL.MYSQLPORT}}` |
| `MYSQLUSER` | `${{MySQL.MYSQLUSER}}` |
| `MYSQLPASSWORD` | `${{MySQL.MYSQLPASSWORD}}` |
| `MYSQLDATABASE` | `${{MySQL.MYSQLDATABASE}}` |
| `DATA_DIR` | `/data` |
| `PUBLIC_CREATOR` | `false` برای شروع |
| `SUPPORT_USERNAME` | یوزرنیم پشتیبانی خودت بدون `@` |

اگر نام سرویس دیتابیس را چیز دیگری گذاشتی، در پنج مقدار `${{...}}`، `MySQL` را با نام دقیق همان سرویس عوض کن. این‌ها Reference Variable هستند، نه مشخصات دیتابیس قدیمی.

برای ساخت APP_SECRET در Terminal همان Codespaces:

```bash
openssl rand -hex 32
```

خروجی را کپی و در Variables وارد کن. آن را برای این پروژه ثابت نگه دار؛ تغییرش وبهوک‌ها را دوباره ثبت می‌کند.

## ۷. دامنه و اتصال خودکار تلگرام

۱. Settings سرویس برنامه → Networking / Public Networking → Generate Domain.
۲. اگر پورت خواست، `8080` بده و متغیر `PORT=8080` هم در سرویس برنامه بگذار. اگر از PORT خودکار Railway استفاده می‌کنی، Target port باید با همان برابر باشد.
۳. دامنهٔ تولیدشده را در متغیر `BASE_URL` با `https://` و **بدون `/` آخر** قرار بده:

```text
https://your-project.up.railway.app
```

۴. Apply changes / Deploy یا Redeploy را بزن.
۵. در Logs باید پیام `initialized` و سپس `Webhooks configured.` ظاهر شود.
۶. آدرس زیر را باز کن:

```text
https://your-project.up.railway.app/healthz
```

پاسخ باید `ok: true` داشته باشد. این بررسی اتصال دیتابیس و زنده‌بودن پردازشگر را می‌سنجد؛ به‌تنهایی تضمین نمی‌کند همهٔ قابلیت‌های تلگرام درست کار می‌کنند.

**نیازی به ساخت لینک setWebhook دستی نیست.** برنامه وبهوک دو ربات اصلی را خودش ثبت می‌کند و هنگام ثبت هر فرزند، وبهوک همان را می‌سازد. لینک‌های `/bot.php` و `/Pedar.php` را در مرورگر باز کنی، پاسخ 405 طبیعی است؛ این مسیرها پیام POST تلگرام با رمز مخصوص می‌خواهند.

## ۸. اولین تست واقعی

۱. در ربات مدیریت `/start` بفرست؛ فهرست دستورات باید بیاید.
۲. در ربات اصلی `/start` بفرست؛ منوی فارسی باید بیاید.
۳. در **ربات مدیریت** `addcoin` را بفرست؛ سپس شناسهٔ خودت؛ سپس `1000`.
۴. در **ربات اصلی** `/mycoin` را بفرست و موجودی را ببین.
۵. `/newbot` را در ربات اصلی بفرست و توکن **ربات سوم** را بده. پیش‌فرض، ساخت ربات ۵۰۰ سکه کم می‌کند.
۶. ربات سوم را باز کن، `/start` و بعد `/panel` بفرست.
۷. «افزودن دکمه جدید🔧» را انتخاب کن. جای دکمه را از بالا/پایین تعیین کن؛ نوع «متن تکی🔰» را انتخاب کن؛ سپس نامی مثل «سلام» بده. از «ویرایش دکمه ها✂» همان دکمه را انتخاب کن، «تعیین مطلب🆕» را بزن و متن ساده بده. هر جا منوی فعلی ورودی دیگری خواست، همان را تکمیل کن.
۸. «خروج از پنل🏠» را بزن و دکمهٔ «سلام» را امتحان کن.
۹. با حساب مجاز دیگری ربات فرزند را تست کن: آن حساب نباید بتواند `/panel` را باز کند مگر ادمینش کرده باشی.
۱۰. یک بار سرویس برنامه را Redeploy کن؛ دکمه و موجودی باید باقی بمانند. این تست Volume و MySQL را هم بررسی می‌کند.

قبل از بازکردن ربات‌ساز برای دیگران، این ده مرحله و آزمون‌های انتهای راهنما را انجام بده.

## ۹. تنظیمات اختیاری

| متغیر | توضیح |
|---|---|
| `PUBLIC_CREATOR=true` | ورود عمومی به ربات‌ساز را باز می‌کند؛ پیش‌فرض فقط خودت اجازه داری |
| `ALLOWED_CREATORS` | چند شناسهٔ عددی مجاز با کاما، بدون فاصله؛ مناسب تست خصوصی |
| `REQUIRED_CHANNELS` | کانال‌های عضویت اجباری اصلی با `@` و کاما؛ خالی یعنی غیرفعال |
| `ANNOUNCEMENT_CHANNEL` | کانال آموزش/خبر خودت، بدون `@` |
| `SHOP_CHANNEL` | کانال آگهی فروشگاه خودت، بدون `@` |
| `REVIEW_CHAT_ID` | شناسهٔ گروه خصوصی بررسی آگهی؛ خالی باشد، ادمین اصلی |
| `LOG_CHAT_ID` | مقصد گزارش‌های قدیمی؛ خالی باشد، ادمین اصلی؛ توکن‌ها ماسک می‌شوند |
| `BOT_COST` | هزینهٔ ساخت از ربات اصلی؛ پیش‌فرض ۵۰۰ سکه |
| `ENABLE_REMOTE_PHP` | پیش‌فرض false؛ موتور PHP قدیمی به یک سایت بیرونی وابسته است، اجرای محلی کد کاربر ارائه نشده |
| `JOB_TIMEOUT` | سقف زمان هر کار صف، پیش‌فرض ۹۰۰ ثانیه |

برای عضویت اجباری، ربات مربوطه باید در کانال عضو و برای اطمینان از بررسی عضویت، ادمین باشد. برای انتشار آگهی یا پست در کانال، دسترسی ارسال پیام لازم است. برای حذف پیام گروه، دسترسی حذف لازم است.

تنظیم عضویت اجباری در **ربات اصلی** از Variables است؛ تنظیم عضویت اجباری هر **ربات فرزند** از پنل همان ربات انجام می‌شود.

برای امکانات Inline/اشتراک‌گذاری، در BotFather گزینهٔ `/setinline` را برای ربات فرزند تنظیم کن. برای پردازش پیام‌های عادی گروه، وضعیت Privacy Mode و دسترسی‌های ربات را در BotFather و گروه بررسی کن؛ در صورت نیاز `/setprivacy` را تنظیم و دوباره ربات را به گروه اضافه کن.

## ۱۱. بکاپ و به‌روزرسانی

کد در GitHub، داده‌ها در MySQL و فایل‌های ساخته‌شده در Volume هستند. بکاپ کد به‌تنهایی کافی نیست. برای MySQL و Volume برنامه، قابلیت Backup در حساب Railway را بررسی و فعال کن. قبل از حذف جدول، ریست، تغییر بزرگ یا جابه‌جایی سرویس‌ها بکاپ بگیر. حذف پروژه یا Volume می‌تواند داده‌ها را از بین ببرد.

برای به‌روزرسانی کد، تغییرات را در GitHub Commit/Push کن؛ Railway را Redeploy کن. در شروع، قالب ربات‌های ثبت‌شده بازسازی می‌شود؛ دکمه‌ها و داده‌ها از MySQL خوانده می‌شوند. متغیرها، Volume و دیتابیس را نگه دار.

فرمان `update` در ربات مدیریت فقط «خبر نسخه و توضیحات» ثبت می‌کند؛ کد جدید دانلود نمی‌کند. `updateallbot` همهٔ فایل‌های فرزند را از قالب **فعلی** بازسازی می‌کند. از نام نسخهٔ متفاوت با `6.0-railway` فقط زمانی استفاده کن که واقعاً کد/نسخه را تغییر داده باشی.

حذف ربات در لایهٔ بازسازی‌شده، وبهوک و ثبت فعال آن را حذف می‌کند ولی جدول‌ها را برای بازیابی باقی می‌گذارد. این تفاوت عمدی با پاک‌کردن کامل قدیمی است. اگر دوباره همان ربات را با توکن معتبر ثبت کنی، داده‌های باقی‌مانده قابل استفاده‌اند. این کار ۵۰۰ سکهٔ ساخت را دوباره می‌گیرد؛ هزینه را در نظر بگیر.

## ۱۲. عیب‌یابی

| مشکل | چه چیزی را بررسی کنم؟ |
|---|---|
| Missing variable | متغیر روی سرویس برنامه وارد نشده یا نامش اشتباه است |
| Database initialization failed | MySQL روشن است؟ Referenceها به سرویس درست اشاره می‌کنند؟ MySQL خالی است؟ |
| Volume is not writable | Volume با مسیر `/data` به برنامه متصل است؟ |
| Build خطا دارد | تب Build logs و خطای PHP/آزمون را بخوان؛ فقط Successful بودن مرحلهٔ دانلود کافی نیست |
| برنامه سبز است ولی ربات ساکت است | BASE_URL، توکن درست، پیام Webhooks configured و استارت خود ربات را بررسی کن |
| 403 روی مسیر وبهوک | بازکردن دستی بدون هدر محرمانه طبیعی است؛ وبهوک ثبت‌شده را دستی دستکاری نکن |
| کاربر دیگری اجازه ندارد | PUBLIC_CREATOR پیش‌فرض false است؛ ALLOWED_CREATORS یا تنظیم عمومی را بررسی کن |
| سکه برای ساخت کافی نیست | از ربات مدیریت `addcoin` و شناسهٔ خودت استفاده کن |
| توکن تکراری/مربوط به ربات دیگر | برای ساخت از ربات سوم، برای تغییر توکن از همان ربات انتخاب‌شده استفاده کن |
| /panel در ربات اصلی کار نمی‌کند | پنل دکمه‌سازی متعلق به **ربات فرزند** است؛ مدیریت مرکزی `/help` دارد |
| عضویت اجباری گیر می‌کند | ربات باید به کانال دسترسی داشته باشد؛ یوزرنیم و ادمین‌بودنش را بررسی کن |
| داده بعد از Redeploy می‌پرد | سرویس به همان MySQL وصل است؟ Volume همان `/data` است؟ |
| متن محتوا ارسال نمی‌شود | قالب HTML و نشانه‌های خاص متن را بررسی کن؛ ابتدا یک متن سادهٔ بدون تگ امتحان کن |
| API/RSS/PHP جواب نمی‌دهد | این بخش‌ها به پاسخ سرویس بیرونی بستگی دارند؛ PHP از راه دور پیش‌فرض خاموش است |
| صف failed یا uncertain دارد | `/status` در مدیریت؛ خطای شماره‌دار را با Logs تطبیق بده. عملیات مالی را کورکورانه تکرار نکن |
| آمار نمودار دقیق ماهانه نیست | ساختار قدیمی روزِ ماه را ذخیره می‌کند، نه تاریخ کامل؛ نمودار تاریخی بلندمدت محسوب نمی‌شود |

توکن، رمز دیتابیس، APP_SECRET و متن پیام کاربران را در اسکرین‌شات خطا نشان نده. لاگ‌های جدید عمداً توکن و متن کامل SQL را چاپ نمی‌کنند.
