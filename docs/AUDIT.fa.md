# گزارش بررسی سورس و تغییرات

## محدودهٔ بررسی

ZIP اولیه ۱۴ ورودی و ۹ فایل PHP داشت؛ `index.php` خالی بود. جمع فایل‌های PHP حدود ۲۹٬۱۳۱ خط بود. در شرط‌های مستقیم متن، ۳۷۳ عنوان مجزا به تفکیک فایل استخراج شد: ۳۱۹ در قالب فرزند، ۳۳ در ربات اصلی و ۲۱ در ابزار مدیریت. فرمان‌های جایگزین `/newbot` و مانند آن و callbackها جدا در مرجع توضیح داده شده‌اند؛ این عدد شمار قابلیت‌های مستقل نیست.

بازسازی از نوع **انتقال و اصلاح موتور موجود** است: موتور چندبخشی Haji حفظ شده، لایهٔ اجرای Railway و مسیرهای اصلی مدیریت بازنویسی شده‌اند. این پروژه یک بازنویسی خط‌به‌خطِ کل ۲۹ هزار خط با تضمین تطابق کامل رفتار نیست.

## نقش فایل‌های اولیه

| فایل | نقش واقعی |
|---|---|
| Pedar.php | ربات عمومی ربات‌ساز، امتیاز مرکزی، ارجاع، بازار و مالکیت |
| bot.php | ابزار مدیریتی/آزمایشی روی دیتابیس مشترک؛ صرفاً «ثبت کاربران» نیست |
| Haji.php | قالب جایگزینی USERBOT، APITOKENBOT و ADMINBOT برای هر فرزند |
| Function.php | تاریخ شمسی، تبدیل عدد، RSS، توابع متن/تصویر |
| connect.php | اتصال MySQL ثابت؛ در نسخهٔ جدید با اتصال محیطی جایگزین شد |
| captha.php | ساخت تصویر کپچا؛ املای نام فایل همین بود |
| chart.php | ساخت نمودار آمار با GD |
| search.php | جست‌وجو با خواندن صفحهٔ عمومی کانال تلگرام؛ API خصوصی تلگرام نیست |
| htaccess | تنظیمات هاست قبلی؛ مبنای مسیرهای امن جدید نیست |
| jpgها و font.ttf | دارایی‌های کپچا |
| index.php | خالی |

فایل `String.php` که Pedar می‌خواند در آرشیو نبود. محتوای گمشدهٔ آن قابل بازیابی از این ZIP نیست. به‌جای حدس‌زدن محتوایش، جدول‌ها و ستون‌های قابل استخراج از CREATE TABLE و migrationهای موجود در فایل‌ها به schema.json منتقل و در شروع آماده می‌شوند. فایل‌های داده‌ای مثل karbar.txt، string.json و dokme.json نیز به‌عنوان دادهٔ قبلی در ZIP نبودند.

## ایرادهای مهم یافت‌شده

۱. **توکن و رمز دیتابیس داخل سورس:** توکن‌های ثابت و اتصال به MySQL قدیمی حذف شده‌اند. هیچ توکن قدیمی در بستهٔ خروجی قرار ندارد.

۲. **ارسال توکن به کانال ثابت:** بعضی مسیرهای ساخت/آپدیت توکن را به یک کانال ثابت و حتی با یک توکن گزارش‌گیر جدا می‌فرستادند. درخواست‌های گزارش‌گیر قدیمی حذف و نمایش توکن در متن پیام ماسک شده است.

۳. **دسترسی ویژهٔ شناسهٔ قدیمی:** Haji مالک ربات را برای یک شناسهٔ ثابت بازنویسی می‌کرد. این مسیر حذف شد. ابزار مدیریتی اولیه نیز کنترل دسترسی سراسری کافی نداشت؛ در نسخهٔ جدید فقط مالک اصلی در خصوصی وارد می‌شود.

۴. **دامنهٔ ثابت و تشخیص IP:** دامنهٔ هاست قدیمی و بررسی مستقیم REMOTE_ADDR با پروکسی Railway سازگار نبودند. وبهوک جدید از BASE_URL و هدر secret_token استفاده می‌کند.

۵. **دکمهٔ ساخت نامنطبق:** متن کیبورد «غیرفعال» داشت ولی handler منتظر «خاموش» بود. عنوان یکسان و مسیر جدید ساخت اضافه شد.

۶. **پاک‌کردن رشته‌ها از توکن:** حذف واژه‌هایی مثل file و php می‌توانست توکن معتبر را خراب کند. این دستکاری کنار گذاشته شد؛ اعتبار با getMe سنجیده می‌شود.

۷. **SQL و شناسه‌های بزرگ:** جدول‌های نصب تازه utf8mb4 و شناسه‌های BIGINT دارند. بسیاری از مقدارهای SQL escape شده‌اند و ۲۸۵ فراخوانی insert در موتور فرزند به آرایهٔ پارامتر تبدیل شده است. این به‌معنی گواهی امنیت کامل تمام مسیرهای موتور قدیمی نیست.

۸. **بازنویسی ناقص مالکیت بازار:** انتقال مالکیت صرفاً با تغییر متن فایل در برابر Redeploy پایدار نبود. مسیر خرید جدید creatorid را هم در دیتابیس مرجع تغییر می‌دهد.

۹. **تکرار webhook و پایان زودرس درخواست:** ورودی ابتدا در صف MySQL ثبت می‌شود. کلید ترکیبی route/update_id تکرار یک آپدیت را حذف می‌کند. فایل هر ربات در پردازش مستقل اجرا می‌شود؛ پیام‌های طولانی مستقیماً در درخواست HTTP اجرا نمی‌شوند.

۱۰. **ناسازگاری‌های PHP 8:** شمارش null، نتایج نامعتبر دیتابیس، نام کلاس CURLFile پس از namespace، چند messageid بدون علامت دلار، getKeygroup بدون پرانتز و فونت `95px` از موارد اصلاح‌شده‌اند.

۱۱. **ابزار به‌روزرسانی جمعی گمشده:** فرمان قدیمی فقط update.json می‌نوشت؛ پردازشگرش در ZIP نبود. مدیریت جدید خودش قالب ثبت‌شده‌ها را بازسازی می‌کند.

۱۲. **پنل و ذخیرهٔ محتوا:** فراخوانی بدون ورودی getEditer در /panel و escape دوبارهٔ JSON در ذخیرهٔ مطلب و پاسخ خودکار اصلاح شدند؛ دکمهٔ متن ساده با کاربر آزمایشی دوم بازپخش شد.

## تفاوت‌های عمدی

- دسترسی عمومی ربات‌ساز ابتدا بسته است و با PUBLIC_CREATOR باز می‌شود.
- حذف در **مدیریت مرکزی و منوی اصلی بازسازی‌شده** توقف و حذف از ثبت فعال است؛ جداول برای بازیابی می‌مانند. بعضی ابزارهای قدیمی داخل فرزند همچنان پاکسازی سخت دارند.
- فرمان‌های debug مدیریت مثل getstep حالا کاربر هدف می‌گیرند و فقط به مرحلهٔ خود ادمین محدود نیستند.
- دستورات مخرب مدیریت مرحلهٔ تأیید دارند. `deletetable` محتوای جدول را پاک می‌کند، نه ساختار جدول را.
- توکن در پاسخ، اعلان و گزارش نمایش داده نمی‌شود.
- درخواست‌های عمومی به شبکهٔ خصوصی و پورت‌های غیر HTTP(S) پذیرفته نمی‌شوند؛ APIهای نیازمند redirect ممکن است به URL نهایی نیاز داشته باشند.
- اجرای PHP بیرونی پیش‌فرض خاموش است. موفقیت سرویس بیرونی تضمین نشده است.
- گزینهٔ اسلات در خروجی قابل اجرا نیست؛ انیمیشن‌های معمولی توپ و تاس مستقل از شرط‌بندی هستند.
- نسخهٔ جدید یک worker و یک Replica دارد؛ زمان‌سنج‌های قدیمی حذف محتوا همچنان ممکن است به دریافت آپدیت بعدی وابسته باشند.

## محدودیت‌های باقی‌مانده و مواردی که «وجود نداشت»

- پرداخت بانکی، پرداخت خودکار خرید سکه، صدور خودکار حساب BotFather، یا مدیریت اکانت شخصی تلگرام وجود ندارد.
- فقط با داشتن سورس نمی‌شود کاربران و سکه‌های دیتابیس قدیمی را بازیابی کرد.
- نمودار روزانهٔ اولیه کلید روزِ ماه دارد؛ گزارش تحلیلی صحیح چندماهه نیست.
- قالب قدیمی در بعضی مسیرها نام و متن را ساده‌سازی می‌کند؛ همهٔ جزئیات قالب‌بندی و ترکیب‌های زبان الگو هنوز تست زنده نشده‌اند.
- crash وسط یک عملیات قدیمی می‌تواند نتیجهٔ نامطمئن داشته باشد. چنین پیام‌هایی خودکار دوباره اجرا نمی‌شوند تا امتیاز یا عملیات تکرار نشود؛ در `/status` با failed/uncertain مشخص‌اند.
- دیتابیس قدیمیِ واقعی و کار با نسخه‌های ناشناختهٔ آن آزمایش نشده است؛ راهنما برای نصب تازه است.
- بستهٔ Docker، اتصالات واقعی Railway، سرعت تحت بار و تحویل پیام واقعی تلگرام باید در محیط خودت آزموده شوند. گزارش VALIDATION دقیقاً می‌گوید چه آزمون‌هایی اینجا اجرا شده‌اند.

## ترتیب تست پذیرش قبل از استفادهٔ عمومی

راه‌اندازی دو ربات اصلی → افزایش سکه → ساخت فرزند → دکمهٔ متن ساده → فرم دو مرحله‌ای → پاسخ خودکار → امتیاز و قفل → عضویت کانال → مدیریت گروه → ارسال به چند کاربر آزمایشی → رونوشت → تغییر توکن → انتقال مالکیت → خرید آزمایشی با سکهٔ داخلی → Redeploy → بررسی ماندگاری داده.

هر مسیر را با حساب مالک و یک حساب فاقد مجوز امتحان کن. برای مسیرهای عمومی از موجودی آزمایشی استفاده کن و قبل از پاکسازی/ریست از داده‌ها بکاپ داشته باش.
